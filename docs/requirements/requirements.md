# 要件定義書 (Requirements Definition)

## 1. プロジェクト概要
* **プロジェクト名:** Genkou Sheet (`genkou-sheet`)
* **種別:** Visual Studio Code 拡張機能 (Custom Text Editor & Writing Suite)
* **目的:** 小説・文章の執筆を支援し、エディタ入力画面自体に常時「原稿用紙の格子（マス目）」を敷き、縦書き・横書きで直接タイピングできる執筆環境を提供する。
* **配布・公開形態:** GitHub（オープンソースリポジトリ）および Visual Studio Code Marketplace での一般公開。

---

## 2. コアコンセプトと解決する課題
1. **「プレビュー」ではなく「原稿用紙そのもの」への直接入力:**
   従来の拡張機能では横書きのプレーンテキストで執筆し、別画面で縦書きプレビューを確認する方式が主流であった。本拡張機能は `CustomTextEditorProvider` を用い、緑や赤の罫線が入った原稿用紙のマス目上で直接カーソルを動かして日本語入力（IME変換）を行える体験を実現する。
2. **対象フォルダー限定の動作（他プロジェクトへの非干渉）:**
   普段のコーディング用ワークスペース（TypeScriptやPythonプロジェクト内の `.md` や `.txt`）には一切干渉せず、ユーザーが明示的に「執筆フォルダーとして有効化」したワークスペース内でのみ機能する。

---

## 3. 機能要件 (Functional Requirements)

### FR-01: 対象フォルダー限定の有効化・無効化機構
* **FR-01-1:** コマンドパレットから `Genkou: このフォルダーを執筆プロジェクトとして有効化` を実行すると、対象ワークスペースに `.genkou.json` および `.vscode/settings.json`（`workbench.editorAssociations` 設定）を生成し、対象フォルダー内の `.txt` / `.md` を自動的に原稿用紙エディタで開く。
* **FR-01-2:** 有効化されていない通常のワークスペースでは拡張機能はスリープ状態を維持し、標準エディタの挙動を一切変更しない。
* **FR-01-3:** コマンド `Genkou: 執筆プロジェクト設定を解除` により、いつでも標準エディタ設定へ戻せる。

### FR-02: 原稿用紙カスタムエディタ UI・表示制御
* **FR-02-1 (マス目常時描画):** 未入力領域を含め、1枚400字詰め（標準20字×20行、中央の「柱」・魚尾・ルビ用余白列付き）の原稿用紙グリッドを常時表示する。
* **FR-02-2 (書字方向切替):** 縦書き（標準・右から左へ進行）と横書き（左から右へ進行）をワンクリックおよび設定で切り替えられる。
* **FR-02-3 (罫線カラーテーマ):** コクヨ風の「緑（Green）」、文豪・丸善風の「赤（Red / Sepia）」、および目に優しいダークモード対応テーマを切り替えられる。
* **FR-02-4 (マス目サイズ変更):** 標準の `20字 × 20行` のほか、設定により任意の `文字数 × 行数`（例：`40字 × 30行` 等）にカスタマイズできる。

### FR-03: 直接入力・原稿用紙組版ルール（禁則・ルビ・入力補助）
* **FR-03-1 (直接入力とTextDocument同期):** マス目上での直接タイピング、日本語IME変換、矢印キーによる自然な移動（縦書き時は上下左右の方向を縦書き座標に合わせる）、選択・コピー＆ペースト、Undo/Redo が VS Code 標準の `TextDocument` と双方向同期する。
* **FR-03-2 (ルビ・傍点処理):**
  * 青空文庫形式のルビ（`｜漢字《かんじ》` または `漢字《かんじ》`）および傍点（`《《強調》》`）を解析する。
  * マス目上では**親文字のみがマス目を消費**し、ルビは各行のルビ欄（行間）に配置する。
  * カーソルがルビ対象語に重なった際、またはツールバー／ショートカット操作により、ルビの追加・編集が行える。
* **FR-03-3 (行末禁則処理・ぶら下げ):**
  * 行末（20マス目）の直後に句読点（`、` `。` `，` `．`）や閉じ括弧（`」` `』` `）` `】`）が来た場合、次行の先頭へ送らず、20マス目の枠内（または欄外）にぶら下げ・同居表示する。
* **FR-03-4 (執筆補助):**
  * **会話文ハイライト:** `「… 」` や `『… 』` の会話文を視覚的に識別しやすいカラーでハイライト表示する。
  * **自動一字下げ:** 段落改行（Enter）時に、次行の先頭へ全角スペース（`　`）を自動挿入する（会話文の開始時や設定オフ時はスキップ可能）。

### FR-04: 執筆支援機能（集計・ツリー・組版出力）
* **FR-04-1 (リアルタイム文字数・枚数カウント):**
  * ステータスバーおよびエディタヘッダーに「実文字数（ルビ・制御記号除外）」「空白込み文字数」「400字詰め原稿用紙換算枚数」「現在の実使用枚数・行数」をリアルタイム表示する。
* **FR-04-2 (原稿ツリー管理):**
  * サイドバー（Activity Bar / Explorer View）に執筆フォルダー内の原稿一覧をツリー表示する。
  * 章・シーンの順序並び替え（`.genkou.json` で順序保持）と、ファイル単位・プロジェクト全体の合計文字数および原稿用紙枚数を集計表示する。
* **FR-04-3 (HTML / PDF 組版出力):**
  * 単一ファイル、または原稿ツリー全体の結合原稿を、印刷・PDF保存に最適化されたHTML（原稿用紙マス目付きスタイル／縦書き文庫本スタイル選択可）として出力・プレビューできる。

---

## 4. 非機能要件 (Non-Functional Requirements)
* **NFR-01 (パフォーマンス):** 1ファイルあたり5万〜10万文字（原稿用紙125〜250枚相当）の長編原稿でも、ページ単位の仮想スクロール（またはチャンク描画）により入力遅延なく快適にタイピングできること。
* **NFR-02 (データ安全性):** ファイルの実体は標準のプレーンテキスト（UTF-8 `.txt` / `.md`）として保存され、万一拡張機能をアンインストールしても原稿データが一切失われないこと。
* **NFR-03 (セキュリティ):** Webview の Content Security Policy (CSP) を厳格に設定し、外部通信を行わず完全にローカル完結で動作すること。
* **NFR-04 (保守性・スタイル一元管理):** UIコンポーネントのハードコードされたスタイルを禁止し、単一のグローバルテーマ定義（Design Tokens / CSS Variables）によって色・フォント・余白・サイズを管理すること。
